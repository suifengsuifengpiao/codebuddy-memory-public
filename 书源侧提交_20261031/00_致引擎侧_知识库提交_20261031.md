## 二、知识条目摘要（供你判断要不要收）

### 2.1 站点档案_百草露 —— 一条改变工具链语义的坑

站点：`m.baicaolu.com`（笔趣阁移动模板）。正文全部藏在 `<script>document.writeln(混淆对象.方法('base64'))</script>`，混淆名每次请求都变。

**核心事实**：3.25 的 `@html` **不是 innerHTML** —— `AnalyzeByJSoup.getResultLast` 里先 `select("script").remove()` 再取 outerHtml。所以对这类站用 `@html` 等于**先把正文删干净**，只剩模板提示语（复现长度 127 字符，与真机日志 `诊断[html长度=127,base64块=0]` 完全一致）。

**为什么这条必须收**：它解释了「本地 6088 字符全绿、真机 127 字符全空」这类长期误判的**全部成因**。而且本地工具链此前**也写错了**（`JsoupRuleEval` 的 `html` 返回 innerHTML 且不删 script）——本地工具与真机同错，才让这个 bug 藏了三轮。

**已落地的工具链修正**（技能 v1.15.0）：
- `JsoupRuleEval.java`：`html` 改为「删 script/style 后**单条** outerHtml」，新增 `all`
- `test_parse.py`：末段 `html`/`all` 强制走真 Jsoup 通道，不再用 bs4 近似
- `evals/jsoup_realdevice_equiv.py`：新增「正文藏在 script 里」夹具 + 4 条 golden，把差异钉死

### 2.2 站点档案_手机小说 —— 「最短 N 字符」闸的通用解法

站点：`wap.shoujixs.net`。搜索拒绝短关键词，提示「最少 10 个字符」。

**根因两层**：PHP `strlen()` 数的是 **UTF-8 字节**（中文 3 字节/字），且 `trim()` **只删半角空白**，全角空格 U+3000 能过。

**关键实测**：

| 写法 | 真机 body | 结果 |
|---|---|---|
| 字面全角空格 `{key}　　` | `searchkey=系统&t=1` | ❌ Legado 发请求前 trim 掉了 |
| 百分号编码 `{key}%E3%80%80×3` | 原样送达 | ✅ |

**通用结论**：「服务端按字节校验 + 客户端会 trim」→ 空白一律写 `%XX`。

### 2.3 站点档案_八叉书库 —— 接口型正文 + Rhino 跨语言两坑

站点：`bcshuku.com`。正文走独立接口 `conapi.php`，令牌嵌在页面 JSON 里。

两坑：`Packages.java.*` 会重绑全局 `java`（之后 `java.log` 报 not a function）；Rhino `ConsString` 走 Map 参数时报 `ConstString cannot be cast to java.lang.String`。解法：`var J = java` 先存住 + 请求头逐个传参不组 Map。

### 2.4 坑点补遗 N10–N13

N10 = `@html` 删 script（同 2.1，技能铁律 27）；N11 = 正文分页变量**跨章陷阱**；N12 = 搜索字节闸；N13 = Rhino 跨语言两坑。

**N11 值得单独看**：站点把「下一页」和「下一章」合并成一个变量（百草露 `hhekgsv`：第1页→第2页，第2页→第2章）。照搬它当 `nextContentUrl`，Legado 会把**整本书拼进第 1 章**。判据是「只接受 `_\d+\.html` 形态」（跨章 URL 不带页码后缀），**不能按章 id 前缀判**——`iytcgscb` 与 `iytcgsci` 前 8 字符相同，前缀比较会误判。

## 三、为什么必须升 v1.15.0（而不是只改书源）

先把可能的质疑挡住：**「你自己改书源就行了，为什么要动我的工具链？」**

因为这次的 bug 不在书源，在**本地验证工具与真机不一致**。

| 环节 | 百草露实际发生的 |
|---|---|
| 书源写 `id.txt@html` | 看似合理——多数站点的 `@html` 就是取内部 HTML |
| 本地 `JsoupRuleEval` 返回 6088 字符 | **全绿**：它实现成了 innerHTML 且不删 script |
| 真机 3.25 返回 127 字符 | **全空**：它先 `select("script").remove()` 再取 outerHtml |

两边都「自洽」，所以本地怎么验都发现不了，直到用户第三次截图报「正文仍空」。**只要本地引擎还留着旧语义，下一个「正文藏在 `<script>` 里」的站点必然重演同样的三轮返工**——这不是一个书源的问题，是工具链的系统性盲区。

所以升版不是顺手：**这条知识要生效，就必须同时改工具。** 只往知识库写一条「`@html` 会删 script」的笔记，下次本地照样返回 6088 字符给你「全绿」的假安全感——文档记事实，工具决定你信不信这个事实。

最低可接受版本：`html` 语义 **与** `all` 指示符两者都对齐。只对齐 `html` 不对齐 `all`，等于告诉后人「别用 @html」却不给替代品，规则会被迫退回正则截取。
