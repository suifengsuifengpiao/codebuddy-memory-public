## M2 角色分离与职责边界（Role Separation & Responsibility Boundary）

**领域**：Agent 系统设计

**核心要点**：将"作者/设计者"与"执行者"、规划与落地严格分离，是反自我说服与反合理化的结构性前提，而非运行时的自觉。职责边界以契约显式声明（如 C-O8 作者≠执行者、C-R1 角色定义），使多 Agent 协作中的归因与验证可指向唯一责任方。清晰的边界把"谁定义目标、谁断言达成"拆成两个主体，从结构上杜绝自证清白。

**关键原则**：
- 设计者不兼任自身产出的验证者（C-V14 验证 Agent ≠ 创作者模型）
- 角色与职责在 SOUL.md 显式注册，不靠隐含约定
- 跨角色信息流经主理人中转，禁止直连（团队协作铁律）

**反模式**：
- 同一个人/模型既写方案又盖章通过（触发 C-V12 元认知拒绝）
- 用"我相信它能做到"替代边界声明
- 边界写进注释却不在契约层落地，降级为装饰

**关联**：承接 M1（Agent 系统设计）的"多 Agent 局限"——边界是化解多 Agent 失控的结构手段；为 M5（自我优化闭环）所引用的"入口分流/引导者模式"提供角色划分基础；与 M41（声明即失效）互补——边界声明若无可执行载体同样失效。

## M3 入口分流与难度路由（Entry Triage & Difficulty Routing）

**领域**：Agent 系统设计 / 路由

**核心要点**：所有请求先经入口分流，按复杂度映射到不同执行路径（C-E11 四级难度路由），避免对简单任务套用重链、对困难任务草率直答。路由决策应以可观测信号（工具调用、耗时、质量三元组 C-E37）为依据而非首因印象。分流点前置到第一响应前，是降低交易成本与返工率的结构性杠杆。

**关键原则**：
- 先判难度再选路径，难度判定本身须可解释、可追溯
- 按场景匹配技能（C-E34 场景路由），skill description 即路由入口（M17）
- 分流结果记入运行记录，支撑后续 EMA 累积（M22）

**反模式**：
- 一律全量走七步闭环，简单任务被重流程拖垮
- 用"看起来像"做路由，无契约依据
- 分流后丢失原始请求上下文，导致下游失真

**关联**：与 M2（角色分离）同属 Agent 系统设计簇，为 M5（自我优化闭环）所引用的"入口分流"提供方法定义；其路由判定为 M7（技能差异化处理）的三级难度路由提供上游依据；输出的难度信号喂给 M22 的 EMA 累积。

## M4 引导者编排模式（Orchestrator / Guide Mode）

**领域**：Agent 系统设计 / 编排

**核心要点**：主理人作为引导者不直接代写成员产出，而是建团队、调度、中转、汇编，使每个专业判断都由其责任主体输出（C-O8 作者≠执行者）。编排模式以消息中转与会话隔离维持职责纯度，避免"一人饰多角"的伪协作。它是七步闭环（C-L4）在团队层面的承载形态。

**关键原则**：
- TeamCreate 只能由主理人执行，严禁委派（团队协作铁律）
- 成员产出回传主理人，由主理人汇总转交，禁止互连
- 任何专业结论以成员原文为准，主理人只做编排

**反模式**：
- 主理人跳过 TeamCreate 自行模拟多角色发言
- 让成员互相直连，信息流脱离中转导致归因丢失
- 为提速而"代写"成员产出，破坏作者≠执行者

**关联**：是 M1（Agent 系统设计）多 Agent 协作的运行形态落地；与 M2（角色分离）、M3（入口分流）共同构成系统设计簇；其编排纪律被 M16（流程治理铁律）的"物理门控"强化——用硬流程而非自觉保证分离。

## M9 信用分配分层（Credit Assignment Hierarchy）

**领域**：能力优化 / 学习

**核心要点**：当一次成功或失败由多步、多技能协作产生时，须按贡献将信用/责任分层归属到具体节点，而非整体好评或整体归咎（Omega-7.6 信用分配分层，MetaAgent-X 启发）。分层信用使经验飞轮（M11）能定位"哪一步真正起作用"，避免把偶然成功误认为能力。它是失败轨迹蒸馏（C-E26）的前置归因框架。

**关键原则**：
- 信用沿调用链逐层下钻，落到最小可归因单元
- 正/负信用分开累计，避免相互抵消掩盖问题
- 信用结果写入运行记录（C-O1），供蒸馏提取

**反模式**：
- 整段任务成功就给所有步骤记功，掩盖拖后腿环节
- 失败一律归咎最后一步，忽略上游根因
- 信用分配靠事后直觉，无结构化归因

**关联**：位于 M8（三能力耦合+退火）之后，为其"选择/利用/蒸馏"提供可量化的归因信号；其分层信用是 M11（轨迹蒸馏+经验飞轮）中"失败是资产"得以成立的前提——先分清楚资产归属；与 M22 的 EMA 累积共享信号基底。

## M10 探索/修复解耦（Explore/Fix Decoupling）

**领域**：能力优化 / 失败处理

**核心要点**：把"探索问题空间（定位、复现、理解根因）"与"修复落地（改代码/改契约）"两个阶段解耦，先充分探索再动手修复，避免边改边猜导致回归扩散（Omega-7.9 探索/修复解耦，SWE-Explore 启发）。解耦使修复可回滚、可独立验证，与 Error-Driven 闭环（C-E12）对齐。它是失败驱动进化（Workflow 4）的方法骨架。

**关键原则**：
- 探索阶段只诊断不修改，产出根因与覆盖缺口
- 修复阶段以前者结论为唯一输入，不复现不修
- 两阶段各自留痕（C-O1/C-O2），支持 replay

**反模式**：
- 一报错就改代码，未复现根因
- 探索与修复混在一步，无法判断哪步生效
- 修复后不回放验证，隐藏连带破坏

**关联**：衔接 M8（三能力耦合+退火）的"利用"与 M11（轨迹蒸馏+经验飞轮）的"失败资产化"——解耦后的轨迹更易被蒸馏；为 Workflow 4（失败驱动进化）提供阶段纪律；与 M16（流程治理铁律）的物理门控同源——用阶段边界防越界。

## M12 经验准入与质量门控（Experience Admission Gate）

**领域**：经验管理 / 蒸馏

**核心要点**：蒸馏产出的经验不是自动入库，须经准入门过滤（C-V18 经验准入门：fitness/is_buggy/distilled_by/independence 四字段），只接收"适配、非缺陷、有来源、可独立"的经验。准入门把 M11 的"失败是资产"从口号变为可审计流程，防止污染性经验进入记忆（呼应 C-E28 记忆投毒防御）。低质经验在门处即丢弃，优于入库后净化。

**关键原则**：
- 每条经验带 distilled_by 溯源，无来源不入
- is_buggy 标记未解决缺陷，阻断缺陷经验传播
- independence 检查保证经验不依赖特定会话上下文

**反模式**：
- 蒸馏即入库，跳过准入门
- 把"这次碰巧成了"当通用经验固化
- 经验无源头，事后无法复盘归属

**关联**：是 M11（轨迹蒸馏+经验飞轮）的下游质量闸门，保证飞轮转的是干净经验；其准入字段与 M22（证据积累与多维度评估）的 EMA 累积共用"可溯源"底座；与 M31（记忆非证据）互补——门内经验亦不自动等于证据。

## M15 软目标诚实治理（Soft-Goal Honest Governance）

**领域**：目标治理 / 知识-行动桥

**核心要点**：对论文、工件、计划等"软目标"做三级诚实分级声明（C-L1 软目标诚实分级声明），目标模糊或连续趋同时按规则动态退出（C-L2 软目标动态退出：连续 3 轮趋同自动退出）。它把"知道什么/能交付什么"的边界显式化，是 K-S-W 三层模型（M14）从知识层落到行动层的治理接口。诚实分级先于执行，是反虚假完成的结构前提。

**关键原则**：
- 软目标按"论文/工件/计划"三级标注达成可信度
- 连续 3 轮无进展自动退出，不靠意志硬撑
- 分级声明写入 SOUL.md，受版本快照保护

**反模式**：
- 把"在读论文"声称为"已内化洞察"
- 目标已趋同仍空转，浪费迭代预算
- 软目标不分级，与硬契约混为一谈

**关联**：衔接 M14（K-S-W 三层模型）的知识/智慧层到可声明行动；为 M16（流程治理铁律）提供"目标确定性"上游——目标不清时（C-E57 目标确定性门控）即在此拦截；其诚实分级与 M37（确认动作的反效果）共同防御自确认陷阱。

## M19 技能健康巡检与自动退化（Skill Health Patrol & Auto-Degradation）

**领域**：技能治理

**核心要点**：技能不是上线即永生，须按日多维健康分巡检（C-E47 技能健康巡检：5 维健康分），低于阈值触发自动退化/归档（C-E45 生命周期 + C-E48 生态仪表盘），把"僵尸机制"在造成污染前回收（Omega-11.0/14.0）。巡检数据汇入生态仪表盘，使技能存活性可观测、可干预。它是技能基础设施（M18）从"建好"到"养好"的运营闭环。

**关键原则**：
- 每日 5 维健康分（调用/质量/成本/依赖/时效）自动计算
- 退化触发走 C-E44 变更门控，不静默删除
- 巡检结果可视化（C-E48），异常上报警报

**反模式**：
- 技能上线后无人巡检，悄然沦为僵尸（呼应 M35/M41）
- 退化靠人工发现，滞后于污染
- 健康分口径不统一，跨版本不可比

**关联**：是 M18（技能基础设施）全生命周期的运营延伸；其退化动作被 M20（血缘驱动进化）的图溯源约束——退化前先查血缘影响面；与 M35（存活性优先于覆盖性）、M41（声明即失效）共享"活比多重要"的判断基准。

## M23 评估标准协同进化（Evaluation-Standard Co-Evolution）

**领域**：评估 / 进化安全

**核心要点**：评估标准本身会随系统能力漂移，须与系统协同进化而非冻结（Omega-10.10 评估标准协同进化，C-E51 自检），防止用过时标尺得出虚假"已优化"。标准进化须可审计、可回滚，与证据累积（M22）共用同一数据基底。它把 AHE 可观测性（M24）的"预测验证"从单次校验升级为持续校准。

**关键原则**：
- 评估标准变更走 C-O2 变更清单，记录动机与影响
- 标准与系统版本对齐，旧版结果不与新版混比
- 自检（C-E51）定期复核标准是否仍贴切

**反模式**：
- 拿 v10 的标准去评 v18 的能力，得出伪结论
- 标准悄悄改，历史评估无法复现
- 用"我觉得达标了"替代标准自检

**关联**：处于 M22（证据积累与多维度评估）与 M24（AHE 可观测性驱动进化）之间——是前者的评估层、后者的预测验证闭环的上游校准；其协同进化纪律与 M40（过度设计的实证收敛）同源——都以实测基线约束主观判断。

## M26 记忆重建优先范式（Memory Rebuild-First Paradigm）

**领域**：记忆系统

**核心要点**：记忆以"可重建"为首要属性，优先保留能重新生成结论的源信号与过程，而非堆砌固化结论（Omega-7.5 记忆重建优先范式）。重建优先降低记忆投毒的不可逆损害，并在上下文压缩（M32）时保住可恢复性。它与记忆分层（M1）配合：分层决定存什么，重建优先决定怎么存。

**关键原则**：
- 存"如何得出"优于存"结论本身"
- 重建路径写入记忆元数据，缺失则降级为低置信
- 压缩/flush 前优先重建，衔接 C-E33a

**反模式**：
- 只记结论不记来路，污染后无法溯源
- 把一次性推论当永久事实写入
- 重建成本被忽略，导致记忆越积越脆

**关联**：是 M1（Agent 系统设计）记忆分层理念的运行范式化；其"源信号优先"为 M27（时序记忆与语义矛盾检测）提供写入纪律；与 M31（记忆非证据）一致——重建出的内容仍非证据，需验证。

## M27 时序记忆与语义矛盾检测（Temporal Memory & Semantic Conflict Detection）

**领域**：记忆系统

**核心要点**：记忆按时间组织（C-M1 时序记忆），写入时做语义矛盾检测，冲突项标记而非静默覆盖（C-M2 语义矛盾检测+写入权限）。需用户确认的高冲突写入才落库，普通冲突留痕待裁。时序维度使"当前事实"与"历史事实"可共存，支撑后续时序状态标签（M30）。

**关键原则**：
- 新记忆与存量做语义比对，命中冲突即标记
- 覆盖须显式授权（C-M2 用户确认才写）
- 时序索引保留矛盾两端，不丢历史

**反模式**：
- 新信息直接覆盖旧记忆，丢失演化轨迹
- 冲突不标记，下游误以为一致
- 无时序索引，无法判断"哪个当前"

**关联**：承接 M26（重建优先）的写入纪律；其语义矛盾标记为 M28（记忆投毒防御）提供检测接口；与 M30（记忆时序状态标签）共享时序底座，并衔接 M31（记忆非证据）对"写入≠正确"的约束。

## M28 记忆投毒防御（Memory Poisoning Defense）

**领域**：记忆系统 / 安全

**核心要点**：对写入记忆的内容做污染检测与分类隔离（C-E28 记忆投毒防御，Omega-7.3 三层分类 + 级联幻觉断裂），阻断被污染记忆向上游推理扩散。防御在写入侧与读取侧双置，防止单点污染引发级联幻觉。它与 M27 的语义矛盾检测、M29 的管线防御构成记忆安全三段。

**关键原则**：
- 写入侧按来源可信度分层，低信源隔离待核
- 读取侧做污染命中检测，命中即熔断推理
- 污染样本计入运行记录，供经验准入（M12）参考

**反模式**：
- 来者不拒全量入记忆，污染面无边界
- 仅在读取侧防御，写入已污染仓库
- 污染事件不记录，无法复盘扩散路径

**关联**：是 M27（语义矛盾检测）在安全性上的强化；与 M29（持久化管线投毒防御）构成"写入—持久化"两段防御；其级联断裂思想被 M33（分层安全治理）的四层门控吸收。

## M29 持久化管线投毒防御（Persistence Pipeline Poisoning Defense）

**领域**：记忆系统 / 安全

**核心要点**：记忆从运行态落盘到持久化管线的全过程须防投毒（Omega-17.0 持久化管线投毒防御 P0），在序列化、传输、落库各环节设校验与签名，防止静默篡改。管线是记忆投毒（M28）的下游延伸，一旦落盘污染更难发现，故列为 P0。它与版本快照（C-E46）协同，使被污染版本可回滚。

**关键原则**：
- 管线各环节带校验和/签名，篡改即失效
- 落盘前与运行态做一致性比对
- 污染版本借 C-E46 快照回滚，不手工修

**反模式**：
- 序列化不校验，落盘即信任
- 只防运行态，忽略持久化链路
- 污染后发现无快照，只能手动清

**关联**：是 M28（记忆投毒防御）向持久化链路的延伸；与 C-E46（版本快照与回滚）共用回滚底座；其 P0 等级与 M33（分层安全治理）的高风险门控口径一致。

## M30 记忆时序状态标签（Memory Temporal State Labels）

**领域**：记忆系统

**核心要点**：每条记忆带时序状态标签 current/old/transition（C-M3 记忆时序状态标签，Omega-13.0/17.0），并配更新决策五态，使"这条还管用吗"可被机器判断而非靠人脑回忆。标签驱动记忆的 flush、压缩与回收优先级，是上下文压缩（M32）前的必做分类。它与 M27 的时序底座衔接，把"时间"变成可操作字段。

**关键原则**：
- 状态随证据更新自动迁移，不靠人工维护
- transition 态须显式决策，禁止长期悬置
- 标签决定 flush/压缩优先级（衔接 C-E33a）

**反模式**：
- 记忆无状态，全库一视同仁
- transition 长期不决，下游无法采信
- 状态靠注释维护，与实际脱节

**关联**：是 M27（时序记忆）状态字段化的落地；其标签输出直接喂给 M32（上下文压缩）决定保留/压缩；更新决策五态与 M31（记忆非证据）共同约束"状态变化≠事实变化"。

## M31 记忆非证据与边界诚实（Memory≠Evidence & Boundary Honesty）

**领域**：记忆系统 / 诚实

**核心要点**：记忆不是证据，人类在环也不自动等于正确（C-M4 记忆非证据，Omega-13.0；叠加 C-E32 能力边界诚实）。内化知识、历史结论、用户确认都只是线索，断言正确性前须独立验证。它与"声明即失效"（M41）、"确认动作反效果"（M37）构成诚实三件套，从记忆侧堵住自确认陷阱。

**关键原则**：
- 记忆值作线索，断言前须可计算验证（C-E49）
- 用户确认降低但不消除验证义务
- 内化知识标注"非实测证据"，不混入事实快照

**反模式**：
- "我记得之前是对的"当作已验证结论
- 用户点过确认就跳过验证
- 把记忆数当实测值写进报告（资产级模式铁律）

**关联**：是 M30（时序状态标签）的语义护栏——状态变化不自动赋予证据地位；与 M12（经验准入门）呼应"门内仍非证据"；与 M37/M41 同属诚实纪律簇，且是资产级模式（team-lead SOP）"内化知识隔离标注"的方法论依据。

## M32 上下文压缩与渐进式压缩（Context Compression & Progressive Compression）

**领域**：上下文工程 / 记忆衔接

**核心要点**：长上下文按四层渐进压缩（C-E52 四层渐进压缩，Omega-10.8），先摘要后提炼，保留可重建的源信号（呼应 M26），在压缩前执行记忆 flush（C-E33a）防止丢证据。压缩是 M25（独立上下文窗口）在单窗口内的延伸——窗口有限时靠压缩维持有效上下文。它与记忆系统（M26-M31）共享"保留可重建"原则。

**关键原则**：
- 四层递进：原始→分段摘要→主题提炼→结论指针
- 压缩前先 flush 记忆，避免源信号丢失
- 压缩率可调，高风险任务降压缩保细节

**反模式**：
- 一次性截断，丢源信号不可重建
- 压缩不 flush，记忆与上下文脱节
- 所有任务同压缩率，关键任务被压糊

**关联**：是 M25（数据分片+独立上下文窗口）在窗口内的互补手段；其"保留可重建"与 M26（重建优先）同原则；flush 纪律衔接 M30/M31 的记忆体系，并作为 M33（分层安全治理）前最后一道上下文净化关。
